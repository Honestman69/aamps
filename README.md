# aamps · AI 智能体接入多平台管理系统

给 AI 智能体配置独立的平台账号，接入 QQ、抖音、B站……让它**活得像个人**。

第一个落地的平台是 QQ（NapCat / OneBot 11）。其他平台以独立适配器包的形式接入，不在主服务里混合开发。

> 当前状态：**私聊已经能对话、群里会克制地插话**；管理后台可用（实例 / 人设 / 密钥 / 素材）。
> 准确的进度与验证数据只看 [`docs/STATUS.md`](docs/STATUS.md) —— 本文**不重复写数字**，
> 那是文档最容易过期的地方（上一版就写着"代码未开始"，而那时已经写到 M3 了）。

## 现在能做什么

- **管实例**：一个平台账号一条实例，QQ 走 NapCat（OneBot 11），反向 / 正向两种接法
- **管人设**：身份、补充设定、示例对话、软禁区、行为参数（发言阈值、打字节奏）、故障话术；
  带草稿 → 发布 → 启用（改已发布内容即新版本）
- **管密钥**：多厂商 API Key 信封加密，界面上只有掩码；预算挂在实例上，超限降级或静默
- **管账号**：管理员可以再建普通用户；两人各自登录、各自解锁，互相看不到对方的实例、人设、
  密钥与素材（一人一份密钥库，管理员也解不开别人的 Key）
- **多模态**：看图（独立视觉模型）、用图片/表情回、发语音（TTS）；素材库可存、可取、可删
- **像个人**：发言决策（群聊大部分消息不回）、内心独白 → 外显、拆条与打字延迟、群里回 @
- **记得住**：每聊够一段就自己总结（摘要 + 关于这个人的事实），下次接着聊不用重新认识
- **看记录**：会话列表 + 消息原文（含被拦截的回复与它的内心独白），只读，按 id 翻页
- **查审计**：谁在什么时候动了什么（改前/改后排开看），一键重算哈希链并指出断在第几条
- **后台**：登录 / 实例 / 设置 / 人设 / 密钥 / 素材 / 会话 / 用户 / 审计九块，构建产物由主服务同源托管

## 还没做的（别按目录名以为有）

| 能力 | 现状 |
|---|---|
| 人格演化（`SelfState`） | 记忆有了，但"它自己变成了什么样"还没有载体 —— 自述、特质数值、版本回滚属 M5-2 |
| 记忆检索（向量 / FTS） | 现在按"人取事实、会话取摘要"的固定规则读回，没有语义检索 |
| 规则引擎 / 输入拦截 / 输出审核 | `rules/`、`compliance/` 空目录 |
| 主动消息 / 定时任务 | `src/workers/` 空目录 |
| 看板与告警 | `observability/` 空目录 |
| 语音识别（收到的语音转文字） | 未做，入站语音仍是「[语音]」占位 |
| 上传素材到库 | 素材只能从对话里存进来，没有上传通道 |
| 删除账号 / 转移实例所有权 | 只支持停用：实例、人设、Key、素材都挂在他身上，删人要连带迁移 |
| 审计导出 / 时间范围筛选 | 审计页只能按关键词与模块筛最近 500 条，没有导出与时间区间 |
| 消息搜索 / 导出 | 会话查看只能"按时间翻"，没有关键词检索与导出 |

## 四条设计前提

1. **走第三方协议**，因为要求机器人和正常用户拥有一样的完整功能。
2. **优先拟人**，评判标准是"像不像人"，不是"功能全不全"。
3. **纯自用，但按多租户的形状组织代码**，后期能改造成共享服务。
4. **平台适配器独立成包**，新增平台是一个新子项目，不碰主服务与前端。

另有一条安全底线：**用户上传的 API Key 只有本人能看到明文，部署者也不行。**

## 技术栈

NestJS + Prisma + SQLite + Vue 3，OneBot 11 接入。

部署目前就是"一台机器 + 一个进程"：`pnpm build && pnpm web:build` 之后跑
`node dist/src/main.js`，页面与接口同源。**容器化还没做**（这一版不写没做的东西）。

详细选型理由见 `docs/ARCHITECTURE.md` 第 2 节。

## 项目结构

这是一个 pnpm workspace，主服务与平台适配器分离：

```
packages/contracts     @newjob/contracts   主服务与所有适配器唯一的共享依赖
packages/adapter-qq    @newjob/adapter-qq  QQ 适配器（独立包）
src/                   主服务：编排、人设、模型、记忆、合规
```

想让 AI 也住进抖音或 B站？新建一个 `packages/adapter-douyin`（实现 `IAdapter` + `manifest`）就能被
`AdapterRegistry` 认出来，主服务不用改。详见 `docs/DECISIONS.md` 的 D013。

> 表单是**清单驱动**的（D041）：适配器在 `ConfigField.mapsTo` 里说明"这个值写进实例的哪个槽位"，
> 前端只负责按清单问问题，主服务按同一张清单翻译。所以"加一个平台"确实只动适配器包。

## 开始开发

```bash
pnpm install
cp .env.example .env      # 填入 DATABASE_URL 等
pnpm prisma migrate dev
pnpm dev
```

首次启动需要创建一个 superadmin 账号，见 `docs/STATUS.md` 的 M0 任务。

### 管理后台

`web/` 是 Vue 3 + Vite 的后台，**由主服务同源托管**，不用另跑一个服务：

```bash
pnpm web:build     # 构建到 web/dist（主服务启动时自动托管）
pnpm dev           # 然后打开 http://127.0.0.1:3000/ 就是登录页
```

改造前端时用两个进程（Vite 热更新 + 后端）：

```bash
pnpm dev           # 后端 :3000
pnpm web:dev       # 前端 :5173，/api 由 Vite 代理到 3000
```

> 没有构建 `web/dist` 也能起服务 —— 只是没有页面，接口照常可用（日志里会提示一行）。

部分动作（连接实例、接口自检）仍有脚本，适合脚本化或在没有界面时用：

```bash
# 登录（= 验密码 + 解锁 DEK）→ 列出实例 → 连接选中的实例
ADMIN_USERNAME=你的用户名 ADMIN_PASSWORD=你的密码 pnpm tsx scripts/connect-instance.ts

# 接口自检（自己建账号、跑完整鉴权与实例流程，不碰真实数据）
BASE_URL=http://127.0.0.1:3000 pnpm tsx scripts/http-smoke.ts
```

**账号从哪来**：首次启动时，服务会用 `.env` 里的 `BOOTSTRAP_ADMIN_USERNAME` /
`BOOTSTRAP_ADMIN_PASSWORD` 创建一个 superadmin；账号已存在则跳过（不会覆盖密码）。
所以"我没注册过账号"不代表没有账号——先看这两行。
如果密码写成 `BOOTSTRAP_ADMIN_PASSWORD="xxx"`，命令行里要连引号一起去掉，或者交给
`scripts/connect-instance.ts`，它会自己剥一层引号（引号带着传进去只会得到一个莫名的 401）。

接口清单看 `src/modules/*/*.controller.ts`，`GET /api/adapters` 会返回各适配器的 `configFields`，
M4 的配置表单就是照着它渲染的。

## 风险提示

本项目通过第三方协议接入 QQ，**存在账号被风控或封禁的风险**。系统内建了行为拟人（发送节流、夜间静默、频率上限、风控自动降级），但这只能降低概率，不能消除。

建议使用小号，并在首次运行时把风控参数调得比默认值更保守。
